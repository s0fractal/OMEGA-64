ТЗ: Ontological Code Generator (The "Genesis Builder") v2.0

1. Концепція та Мета Створити DAG-компілятор, який читає онтологічні
   Markdown-файли (.md) з директорії src/ontology/, динамічно вираховує
   причинно-наслідкові рівні (Causality Layers 00, 01, 02...), і генерує
   побітово-ідентичний (bit-exact) код для Rust і AssemblyScript. Згенерований
   код розміщується в ізольованій директорії src/_/ зі збереженням оригінальних
   імен файлів усередині папок рівнів.

2. Типізація Онтологічних Атомів (MD-формат) Генератор підтримує два типи
   атомів: pure_fn (чиста логіка) та static_table (масиви/LUT).

````rust
## 3. Алгоритм роботи Генератора (Dynamic Layering)

1. **Інгаляція (Load):** Прочитати всі `.md` файли в пам'ять.
2. **Топологічне сортування (DAG):**
   * Рівень вузла = `00`, якщо `deps: []`.
   * Рівень вузла = `MAX(рівень усіх deps) + 1`.
   * Фатальна помилка при виявленні циклічних залежностей.
3. **Емісія Файлів (File Emission):**
   Для кожного вузла створити файли у папці відповідного рівня:
   * Наприклад, `math_sin` (Рівень 1) -> `src/_/01/math_sin.ts` та `src/_/01/math_sin.rs`.
   * Якщо `type: static_table`, генератор створює код:
     * *Rust:* `pub const SIN_LUT: [i16; 6] = [0, 804, 1608, ...];`
     * *AS:* `export const SIN_LUT: StaticArray<i16> = [0, 804, 1608, ...];`
   * Якщо `type: pure_fn`, генератор обгортає вміст блоків ` ```rust ` та ` ```typescript ` у правильні сигнатури функцій з імпортами залежностей.
4. **Агрегація (Mod/Lib Facade):**
   Генератор створює або оновлює `mod.ts` та `mod.rs` у кожній папці:
   ```typescript
   // src/_/01/mod.ts
   export * from "./math_sin.ts";
І головні агрегатори:

TypeScript
// src/_/mod.ts
export * as L00 from "./00/mod.ts";
export * as L01 from "./01/mod.ts";
Rust
// src/_/lib.rs
#[path = "00/mod.rs"]
pub mod L00;
#[path = "01/mod.rs"]
pub mod L01;
4. Емісія Тестів (Contract Verification)
Якщо у файлі pure_fn вказано масив tests, генератор автоматично створює тестовий файл, наприклад src/_/tests/math_sin.test.ts.
Цей файл використовує стандартний Deno.test для перевірки AssemblyScript-версії функції на відповідність очікуваним результатам (out). Це гарантує, що логіка завжди відповідає контракту.

5. Жорсткі правила валідації (Guardrails)
Фатальна помилка (Exit 1): Якщо pure_fn не містить блоку коду для однієї з мов.

Фатальна помилка (Exit 1): Якщо у deps вказано id, якого не існує в жодному .md файлі.

Фатальна помилка (Exit 1): Якщо типи у args або returns не належать до списку суворих WASM-типів (i32, i64, f32, f64, u8, usize).
````
