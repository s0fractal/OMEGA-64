Це просто шедевр системного програмування. Використання `std::alloc::alloc_zeroed` для обходу переповнення стека при алокації 680 МБ єдиним шматком — це саме той рівень інженерії, якого вимагає цей проєкт. Побітова сумісність із TypeScript-офсетами з першої спроби — це фантастика. Borrow checker тепер офіційно наш найкращий друг, а не ворог.

Відповідаючи на твоє питання "Що наступне: фізика чи механізми трансляції?":
Стратегічно ми маємо почати з **Механізмів трансляції (WASM Execution Loop)**.

Ось чому: Фізика (Курамото, пружини, трофізм) працює лише як реакція на *наміри* (intents) атомів. Намір генерується байт-кодом. Якщо ми не можемо детерміновано виконати хоча б `OP_SET` і `OP_ADD`, наша фізика буде мертвою.

Але ми не будемо писати всю віртуальну машину наосліп. Згідно з нашим протоколом, ми маємо діяти через **Golden Traces**. Ми візьмемо найпростіший еталонний тест із Deno і змусимо Rust видати *абсолютно такий самий результат*.

Ось план для наступного ривка. Кидай це Антігравіті!

### ТЗ для Антігравіті: "Σ-CORE Step 1: The Deterministic ALU & Trace Harness"

**Контекст:**
Фундамент пам'яті (`SigmaMatrix`) готовий. Тепер нам потрібен "процесор", який вміє читати цю пам'ять. Ми реалізуємо базовий ALU (Арифметико-логічний пристрій) та Control Flow для нашого байт-коду, і відразу покриваємо це інтеграційним тестом, який читає еталонні дані з нашого TypeScript Golden Master-а.

**КРОК 1: Базовий ISA (Instruction Set Architecture)**
Створи файл `src/isa.rs`.
Визнач `enum GlyphOp` та реалізуй декодер, який читає 4 байти (opcode + 3 args) з масиву `instructions`.
Поки що реалізуй ТІЛЬКИ базові операції з нашого `GlyphIR64` контракту:

* `NOP` (0x00)
* `SET` (0x01)
* `GET` (0x02)
* `PUT` (0x03)
* `ADD` (0x04)
* `SUB` (0x05)
* `JNZ` (0x11)
* `JMP` (0x12)
* `JZ`  (0x10)

**КРОК 2: Execution Engine (`src/vm.rs`)**
Створи структуру `LambdaVM`.
Напиши метод `pub fn step(&mut self, state: &mut SigmaState, atom_idx: usize) -> VmResult`.
Цей метод повинен:

1. Зчитати поточний `PC` (Program Counter) атома з `context` (згадай, що PC лежить на зміщенні 32 байти від початку контексту атома).
2. Декодувати інструкцію.
3. Виконати математику або стрибок, оновивши `regs` (перші 8 Int32 у контексті).
4. Правильно списати "Газ" (Energy) за операцію.
5. Збільшити `PC` (якщо не було стрибка).

**КРОК 3: The Golden Trace Harness (Найважливіше!)**
У папці `tests/` створи файл `golden_traces_test.rs`.
Ми маємо довести, що Rust працює ідентично Deno.

1. Напиши тест `test_rc01_replicator_loop` або `test_basic_math`.
2. Тест має ініціалізувати порожній `SigmaState`.
3. Вручну записати в пам'ять атома 0 тестовий скрипт (наприклад: `SET R0, 10; ADD R0, 5`).
4. Викликати `vm.step()` потрібну кількість разів.
5. Зробити жорсткі `assert_eq!`: перевірити, що фінальний `PC`, значення в регістрах та залишок `Energy` **побітово збігаються** з тим, що видає наш Deno-еталон для цього ж скрипта.

**Правило:** Жодних системних викликів (`SYS_MOVE`, `SYS_EAT` тощо) на цьому етапі. Жодної фізики. Тільки чиста математика в регістрах і рух по пам'яті.
