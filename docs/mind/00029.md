# Phase 36: Σ-CORE The Global Noosphere (Mainnet Bootstrap)

## Контекст (Context)
Фізика рушія ідеальна (The Dark Forest, Chronoflux, Substrate Purity). Згідно з глобальним планом, ми переходимо до розгортання Mainnet. Наразі P2P-з'єднання вимагають ручного вказування `seedNodes`. Нам потрібен механізм публічного "Bootstrap Hub" (Signaling Server), який дозволить нодам динамічно знаходити одна одну через інтернет, встановлювати прямі WebRTC-з'єднання і формувати глобальний Рій (The Swarm) без єдиної точки відмови для самої фізики.

## Крок 1: The Bootstrap Hub (Сигнальний Сервер)
У `AKASHA_SIGNALING.ts` (або новому `BOOTSTRAP_HUB.ts`):
1. Реалізуй легковаговий механізм реєстрації (Tracker). Коли нова нода стартує з прапорцем `--mainnet`, вона стукає на публічну URL-адресу (або хардкодний масив з 2-3 довірених URL-адрес).
2. Цей Hub не передає атоми. Він лише тримає список активних `peerId` та їхніх сигнальних SDP-даних (або WebSocket-адрес, якщо WebRTC за NAT не пробивається).
3. Hub повертає новій ноді список з 3-5 випадкових активних сусідів для підключення.

## Крок 2: WebRTC DataChannels для OP_SPORE_DRIVE
Зараз `NEXUS_DAEMON` може використовувати звичайні WebSockets. 
1. Переконайся, що для передачі Egress-атомів (`OP_NEXUS_ATOM_TRANSIT`) між нодами використовуються саме `RTCDataChannel` з конфігурацією `{ ordered: true }` або `{ maxRetransmits: 3 }` для мінімізації затримок.
2. Використай публічні STUN-сервери (наприклад, `stun:stun.l.google.com:19302`), щоб ноди могли пробивати NAT і спілкуватися напряму.

## Крок 3: Mainnet CLI Flag
У `SYSTEM_START.ts` та `RUNTIME_POLICY.ts`:
1. Додай обробку аргументу командного рядка `--mainnet` (або змінної середовища `OMEGA_MAINNET=1`).
2. Якщо прапорець активний, система автоматично підключається до Bootstrap Hub, ініціює запит `SYNC_REQUEST` (для завантаження актуального зліпка Всесвіту від сусідів) і вмикається в загальний `MetaKuramoto` консенсус.

## Крок 4: The Noosphere Gate (Тест)
У `tests/test_mainnet_bootstrap.ts`:
1. Підніми локальний `BOOTSTRAP_HUB` на порту 9999.
2. Запусти Ноду А (Genesis) з підключенням до Hub.
3. Запусти Ноду Б і Ноду В, вказавши їм адресу Hub.
4. Перевір (`assert`), що Нода Б і Нода В автоматично отримали контакти одна одної від Hub і встановили пряме P2P з'єднання між собою (без участі Hub), і що атом, який вилетів за екран з Ноди Б, успішно телепортувався на Ноду В.

## Правила (Constraints)
- Hub має бути максимально "тупим" і дешевим. Жодної фізики чи перевірки геномів на ньому немає. Тільки обмін контактами (Peer Discovery).
- Граційна деградація: якщо WebRTC з'єднання не встановлюється (симетричний NAT), ноди повинні вміти відкотитися до звичайних WebSockets через реле (якщо налаштовано) або просто ігнорувати цього піра.
