# Phase 31: Σ-CORE The Sovereign Oracle (LLM Genome Synthesis)

## Контекст (Context)

Рій (The Swarm) стабілізовано. У нас є повністю детермінований рушій і
можливість "бачити сни" (Shadow Forking) через `run_shadow_simulation`. Настав
час підключити до цього процесу LLM (Sovereign Oracle). Оракул буде виступати в
ролі "Глобального Еволюційного Тиску": він аналізуватиме стан Матриці, писатиме
нові 64-байтні геноми (AST) для вирішення поточних проблем виживання,
тестуватиме їх у Тіньовій симуляції та ін'єктуватиме успішні варіанти в реальний
світ.

## Крок 1: The Oracle Telemetry (Збір контексту)

У `SOVEREIGN_ORACLE.ts` реалізуй функцію `gatherEpochTelemetry()`:

1. Збери базову статистику Матриці (з `PULSE` або `SigmaState`):
   - Загальна популяція (`population`).
   - Середня енергія (`avg_energy`).
   - 3 найпопулярніші геноми (витягни перші 4-8 байтів їхнього коду, щоб
     ідентифікувати "домінуючі види").
   - Кількість успішних нейронних зв'язків (`synaptic_weights > 0`).
2. Сформуй з цього текстовий промпт (Context Window) для LLM.

## Крок 2: LLM Synthesis Bridge (Генерація Геному)

1. Напиши заглушку або реальний API-виклик до LLM (наприклад, OpenAI/Gemini API
   або локальний Ollama).
2. Промпт повинен чітко інструктувати LLM: _"Ти — еволюційний алгоритм. Ось
   поточний стан середовища. Згенеруй рівно 64 байти нового байт-коду (у форматі
   hex-стрічки), використовуючи нашу систему інструкцій (OP_MOVE, OP_EAT,
   OP_SIGNAL, OP_HEBB тощо), щоб покращити виживання атомів"_.
3. Реалізуй жорсткий парсер `parseLLMResponse(response: string) -> Uint8Array`:
   він має витягувати з відповіді рівно 64 байти і відкидати будь-яке текстове
   "сміття", яке LLM може додати до відповіді.

## Крок 3: The Shadow Filter (Фільтрація Галюцинацій)

Не можна довіряти LLM напряму! У `SOVEREIGN_ORACLE.ts` в циклі еволюції:

1. Коли LLM повертає новий `Uint8Array(64)` геном, передай його у
   `PULSE.simulateFuture(steps: 100, targetIdx: 0, newBytecode)`.
2. Отримай `DriftMetrics` від Rust-ядра.
3. Якщо `population_diff < 0` (атоми вбивають один одного) або метрики гірші за
   базові — відхили геном (`REJECTED_BY_SHADOW`) і попроси LLM згенерувати
   інший.
4. Якщо метрики позитивні — переходь до Кроку 4.

## Крок 4: The Divine Injection (Ін'єкція в Рій)

1. Успішний геном упаковується в `oracle_head_mutation` (або оформлюється як
   `EgressEvent` / Плазміда).
2. Запиши цей байт-код у пам'ять "Нульового Атома" (Genesis Atom) або розпили
   його як інфекцію на кількох випадкових атомів.
3. Логуй подію: `[ORACLE] Divine Intervention applied. Hash: <genome_hash>`.

## Крок 5: The Epistemic Gate (Інтеграційний Тест Оракула)

У `tests/oracle_loop_test.ts`:

1. Замість реального API-виклику LLM, зроби мок (Mock), який повертає масив з
   двома геномами:
   - "Поганий" геном (наприклад, суцільні `OP_DIE` 0x00).
   - "Хороший" геном (простий цикл `OP_REPLICATE` -> `OP_MOVE`).
2. Прожени цикл Оракула.
3. Перевір (`assert`), що Оракул пропустив Поганий геном через Тінь, побачив
   падіння метрик і автоматично його відхилив.
4. Перевір, що Хороший геном пройшов Тінь і був успішно записаний у
   `SigmaMatrix` (перевіривши пам'ять атома).

## Правила (Constraints)

- Безпека пам'яті: Парсер `parseLLMResponse` повинен бути параноїдальним. Якщо
  LLM поверне 63 або 65 байтів, або невалідні hex-символи — викидай помилку, не
  передавай це в Rust.
- Тіньова симуляція (`simulateFuture`) має виконуватися повністю синхронно і не
  блокувати мережеві Heartbeat-и Рою з Фази 29.
