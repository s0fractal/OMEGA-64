# Phase 37: Σ-CORE Information Thermodynamics (Shannon Entropy)

## Контекст (Context)
Ми маємо впровадити строгий зв'язок між інформаційною складністю геному (байт-коду) та його енергетичною вартістю (метаболізмом). Ми використовуємо формулу Ентропії Шеннона ($H = -\sum p_i \log_2 p_i$), щоб оцінити 64-байтний набір інструкцій кожного атома. Атоми з хаотичним (випадковим) геномом матимуть високу ентропію і платитимуть "Податок на хаос" (Noise Tax). Атоми з впорядкованим, структурованим геномом споживатимуть менше енергії.

## Крок 1: Обчислення Ентропії у Rust
У `sigma_core/src/vm.rs` (або `math.rs`):
1. Напиши чисту, швидку функцію `calculate_shannon_entropy(logic: &[u8; 64]) -> f32` (або у fixed-point арифметиці `i32`).
2. Функція має рахувати частоту появи кожного байта (від 0 до 255) у 64-байтному масиві інструкцій.
3. Далі вона обчислює $H = -\sum (count/64) * \log_2(count/64)$. 
4. Максимальна ентропія для 64 байт — це 6 біт (якщо всі 64 байти унікальні). Мінімальна — 0 біт (якщо всі байти однакові, наприклад, 64 нулі).

## Крок 2: Податок на Хаос (The Noise Tax)
У `sigma_core/src/vm.rs` в кінці функції `step` (де розраховується `metabolic_cost`):
1. Викликай розрахунок ентропії для `state.matrix.instructions[atom_idx]`. *(Оптимізація: щоб не рахувати логарифми кожен тік, можна зберігати `entropy_cache` або рахувати її лише при `OP_MUTATE`/`OP_REPLICATE` — обери найефективніший підхід для Rust).*
2. Додай `entropy_penalty` до `metabolic_cost`. Наприклад, якщо ентропія > 4.0 (дуже хаотичний код), податок експоненційно зростає. 
3. Формула: чим вища ентропія Шеннона, тим дорожче обходиться кожен такт обчислень.

## Крок 3: The Thermodynamics Gate (Інтеграційний Тест)
У `verification/reduction_cases.ts` або новому тесті `test_shannon_entropy.ts`:
1. Створи "Впорядкований Атом" (Ordered Atom): геном складається з повторюваного патерну `[0x81, 0x00, 0x00, 0x00]` (тільки 2 унікальні байти).
2. Створи "Хаотичний Атом" (Chaotic Atom): геном заповнений `crypto.getRandomValues(new Uint8Array(64))` (максимальна ентропія).
3. Дай їм однакову стартову енергію (наприклад, 10000).
4. Прокрути симуляцію на 50 тактів.
5. Перевір (`assert`), що "Хаотичний Атом" спалив значно більше енергії (або взагалі помер), тоді як "Впорядкований Атом" зберіг енергію.

## Правила (Constraints)
- Оскільки ми в Rust і не можемо використовувати важкі float-логарифми на гарячому шляху `execute_atom` без втрати продуктивності (500,000 разів за тік), використай наближення (LUT - Look Up Table для `p * log2(p)`) або розраховуй ентропію атома лише один раз при його народженні/мутації і зберігай це значення в пам'яті (`matrix.entropy_i16` або у вільному слоті `context`).
